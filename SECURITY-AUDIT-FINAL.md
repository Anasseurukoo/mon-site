## 1. Executive security summary

The production website is a static Next.js export with no server routes, server actions, database client, or authentication flow in the supplied source. `npm audit --omit=dev` reports zero vulnerabilities. The BBA AI browser client sends bounded text to a separate Supabase Edge Function; the function keeps provider credentials server-side, restricts browser origins, validates content type and message shape/size, enforces a provider timeout, disables caching, and fails closed if its external rate limiter is unavailable.

Five high-severity npm findings remain in a single development-only ESLint dependency path. They all trace to `braces@3.0.3` and one stack-exhaustion denial-of-service advisory. The upstream advisory lists no patched version. npm's proposed forced fix downgrades `eslint-config-next` from 16.4.0 to 14.2.35, which is incompatible with the project's Next.js 16 configuration and does not establish that the vulnerable package is removed. No force fix, unsafe Git dependency override, major downgrade, or package removal was applied.

The GitHub Pages workflow had mutable action tags and granted Pages/OIDC write permissions to the build job. It is now pinned to immutable commits, checkout credentials are not persisted, job permissions are least-privilege, and jobs have timeouts.

## 3. Root causes

- The npm finding originates in the current Next.js ESLint toolchain and an upstream package with no released patch.
- GitHub Actions used conventional floating major tags and workflow-wide permissions rather than immutable revisions and per-job scopes.

## 4. Fixes implemented

- Pinned all five third-party GitHub Actions to the commits currently referenced by their declared major tags.
- Set top-level workflow permissions to none, then granted `contents: read` only to `build` and `pages: write` plus `id-token: write` only to `deploy`.
- Disabled persisted Git credentials after checkout.
- Added 15-minute build and 10-minute deploy timeouts.
- Preserved the application, BBA AI behavior, static export, design, routes, animations, metadata, and dependency versions.

## 8. Remaining risks and limitations

- The development-only `braces` advisory remains until upstream publishes a compatible patch. Do not use `npm audit fix --force` for the suggested Next.js/ESLint downgrade.
- The public BBA AI function intentionally has `verify_jwt = false`. Origin checks stop unwanted browser origins but are not authentication because non-browser clients can forge `Origin`; the Upstash-backed rate limit is therefore essential. Consider a Cloudflare rate limit in front of the function as defense in depth.
- Prompt injection cannot be eliminated solely by a system prompt. The current function limits inputs/outputs and exposes no tools or private retrieval, which constrains impact. Continue avoiding secrets or privileged tools in model context.
- Conversation text is sent to OpenAI. The UI should continue warning visitors not to submit sensitive information, and the production privacy notice should accurately describe processing and retention.
- No Supabase database schema or RLS policies are present in this archive. The site code does not query Supabase tables, so RLS could not be verified and must not be inferred.
- Static GitHub Pages cannot set response security headers itself. Cloudflare behavior and production headers were not accessible from this local audit.

## 9. Manual Cloudflare and Supabase recommendations

### Cloudflare

- Keep SSL/TLS mode at **Full (strict)**, enable **Always Use HTTPS**, and enable HSTS only after confirming every required subdomain supports HTTPS. Start with a short `max-age`; add `includeSubDomains` or preload only after staged validation.
- Add response headers at the edge: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and an appropriate `Permissions-Policy`. Test a report-only CSP first because the static export and Next.js scripts require careful source allow-listing; do not deploy an untested restrictive CSP.
- Do not cache responses from the Supabase AI function. Apply a separate request-rate rule for its path and preserve the real client IP headers expected by Supabase/Upstash.
- Confirm DNS records are proxied only where intended and review cache rules so HTML can be refreshed while hashed `/_next/static/` assets receive long immutable caching.

### Supabase

- Keep `OPENAI_API_KEY`, `UPSTASH_REDIS_REST_URL`, and `UPSTASH_REDIS_REST_TOKEN` only in Edge Function secrets; rotate them if they have ever appeared in source, logs, screenshots, or client variables.
- Verify the deployed function source matches the reviewed local source before any future release. Confirm CORS preflights from both production origins and rejection from unapproved origins.
- Keep `verify_jwt = false` only while the endpoint is intentionally public and rate limiting remains fail-closed. If database tables are later introduced, enable RLS on every exposed table and test anonymous/authenticated policies separately.
- Configure log retention and alerts for sustained 429/5xx responses without logging message contents or credentials.
